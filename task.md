Условия
● При реализации иерархии наследования производный класс должен
расширять суперкласс новыми свойствами, для чего следует разобраться в
предметной области задачи.
● Классы-сущности не следует перенасыщать методами, выполняющими
функциональные действия (методами бизнес-логики, такими как поиск и
т.д.).
● Для сортировок наборов объектов использовать реализацию интерфейса
Comparator.
● При решении задачи использовать паттерны Creator, Factory Method.
● Все классы приложения должны быть структурированы по пакетам.
● Оформление кода должно соответствовать Java Code Convention.
● Параметры, необходимые для создания объектов, должны вводиться с
помощью чтения данных из текстового файла (.txt). Среди данных в файле
должна быть как корректная информация, так и заведомо некорректная
информация. Должна присутствовать обработка (замена значений по
умолчанию или игнорирование) некорректных данных инициализации
объекта.
● Для записи логов использовать Log4J или Log4J2. Допускается SLF4J.
● При логировании использовать вывод логов разного уровня. Логи разного
уровня выводить разным цветом. Логи выводить как на консоль, так и в
файл. Для текущих логов использовать 3 файла, устаревшие файлы логов
архивировать.
● Код должен быть полностью покрыт тестами. Использовать TestNG или
JUnit.
● Пользовательское меню для приложения не реализовывать.
